## 项目背景（省得你再问一遍）

**为什么做这个**：我原来用开源项目 Fud AI 记饮食，但它有四个问题——饮水记录不合理、部分 AI 供应商的 key 根本不适配、AI 对话不现代、中文支持很浅（份量单位全是 `slice/cup/can` 这种西餐体系）。同时它为了健身功能带了一个 1.2GB 的动作图库，而我从不用。所以我抽离出「只记饮食」这一块重做。

**几个关键决策（已经定了，不要重新讨论）：**

1. **技术栈是 React 19 + Vite 8 + Capacitor 8，不用 Flutter、不用原生 Kotlin、不用 Wails。**
   理由：我已有可跑的 Capacitor 工程范式；这个 App 高频操作是「打菜名」，WebView 走系统输入法比 Flutter 自绘 TextField 稳；相机需求浅（拍照→压缩→上传，无 AR、无实时预览）。

2. **不做任何称重、量杯、密度标定。**
   所以不走「拍照→测体积→乘密度→得克数」的几何路线。原因：无实测条件下，容器容积和空隙率都无法标定，误差连乘约 ±45%，反而比 AI 直接判断差。

3. **AI 只做两件事：识别是什么食物 + 判断小份/中份/大份。**
   禁止让 AI 输出克数、热量或任何营养数值。所有营养从本地成分表查。

4. **克数的三条来源，按优先级：**
   ① 用户明确说了克数 → 直接采用
   ② 记忆库命中 → 用历史值
   ③ AI 判档位 → 查档位表（技术文档 §2.4）

5. **复合菜不查表，拆成原料 + 调料逐条查。**
   宫保鸡丁、饺子、包子、奶茶在成分表里都是 0 条，这是事实。拆解时「油一汤匙 = 13.8 g」这类常量换算贡献了 90~180 kcal，是最大的精度收益点。

6. **UI 用 `animal-island-ui`（动森风格组件库）。**
   参考仓库在 `参考/animal-island-ui`（已 gitignore，只读，不要改）。优先 `npm install animal-island-ui`；如果拉不到，退化为 `file:./参考/animal-island-ui`。

7. **Android only。** 我在 Windows 上，无法构建 iOS。

## 数据情况（已经核过，不用再查）

`data-src/food_composition_full.csv` 是 1677 条中国食物成分表数据，37 列，61 个分类。

关键事实：

- `edible` 覆盖率 99.9%，`energyKCal` 98.0%，`water` 96.2%
- 脏值有四种：`—`（无数据）、`Tr`（微量）、`899*`（带星号=计算值）、`un`
- **生熟差异 3 倍**：面条（生）301 kcal vs 面条（煮）107 kcal，UI 必须显示状态标签
- `edible < 100%` 有 699 条（带骨带壳）
- 英文名只有 74.1%（1242/1677）
- `remark` 列是采样产地（河北/广东/上海…），对 App 无用
- **菜肴全部缺失**：宫保鸡丁 0、包子 0、饺子 0、奶茶 0、火锅 0

清洗规则写在技术文档 §5.2，必须按那个实现。

## AI 情况（已经核过）

DeepSeek 官方 API 的 `deepseek-flash` 模型支持图片输入（2026-08 上线）。

关键限制：

- 图片每张最多 **384 tokens**，会被自动缩放到约 **800×800 等效**
- 所以图片压缩参数是**长边 800、JPEG 0.8**，压更大是浪费
- 图片只能放在 **user** 消息里，放 system/assistant 会 400
- 协议是 OpenAI 兼容的 `image_url` 内容块

**P1 的第一步**：先搭工程骨架（`npm create vite` → 装依赖 → 配 Capacitor），再写 `scripts/build-foods.mjs` 把 CSV 转成 `foods.json`。
