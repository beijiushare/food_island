# 录入流程重设计

> 2026-11-25。把「弹窗录入」改成三个独立页面，并让一道菜只占一行。

## 目标

- 加号打开菜单：**输入 / 搜索 / 最近**，三选一
- 全部独立页面，不用弹窗；Android 返回键按路由回退
- 一道菜 = 一条记录，原料作为明细挂在里面
- 所有内容（照片、文字、标题、克数、营养、日期、餐次）都能改
- 图片增删必须真正落盘：删了就删文件，不留尸体

## 页面

```
今天页「+ 添加午餐」
  /add?date=YYYY-MM-DD&meal=lunch     菜单页
    /add/input    照片（可多张）+ 文字 → AI
    /add/search   搜成分表
    /add/recent   最近吃过（次数 → 最近）
      └→ /add/review                  结果卡（多条可改）
            └→ 保存 → 回今天页
```

## 数据模型

```ts
// DiaryEntry 新增
components?: EntryComponent[];   // 复合菜的原料明细
nutrientsManual?: boolean;       // 手改过营养，改克数不再重算

interface EntryComponent {
  name: string;
  grams: number;
  foodCode: string | null;
  nutrients: Nutrients;
}
```

外层条目：`name` = 菜名，`grams` = 原料克数之和，`nutrients` = 原料营养之和。
改外层克数 → 所有原料按比例缩放；改某条原料 → 外层跟着重算。

## 决定（已与用户确认）

| 问题 | 决定 |
| --- | --- |
| 复合菜 | 一道菜一行，原料藏在 `components` 里，可展开改 |
| 多张照片 | 只用于 AI 分析；保存时第一张挂到第一条记录，其余**真删** |
| 时间 | 只改日期 + 餐次，不引入具体时刻 |
| 无 Key 的文字 | 退回本地 `parseSentence`，不能断 |
| 查不到成分表的菜 | 保留一行，营养手填，标 `nutrientsManual` |
| 营养来源 | AI 不返回营养；成分表算，用户可手改并锁定 |

## 图片生命周期

- 拍照即写入 `Directory.Data`，只存相对路径
- 结果卡里删照片 → 立即 `deletePhotoFile`
- 保存时多余照片 → 删除
- 离开 `/add` 流程且未保存 → 清理草稿照片
- 删整条记录 → 删照片文件（已有逻辑）

## 验收

- 三个入口都能完成一次记录
- 「最近」排序：使用次数降序，其次最近使用时间
- 一次输入两张照片 + 一句话 → 结果 → 保存
- 删掉照片后，私有目录里没有残留文件
